# Wiregate — баг-репорт по форме регистрации

**Объект:** https://gitlab.com/rndx2-public/wiregate-test-task (`main`, коммит `8eedbff`)
**Окружение:** Frontend React (http://localhost:3000), Backend NestJS (http://localhost:8000), PostgreSQL. Браузер Chromium (Playwright), десктоп 1280×900 и мобильный 375×812.
**Метод:** ручные и автоматизированные проверки UI через Playwright, запросы к API через curl, проверка данных в БД, ревью исходников.
Подтверждения: видео `demo-bugs.webm`, скриншоты в `screenshots/`, сценарий `demo-bugs.js`.

Серьёзность: 🔴 Critical / 🟠 Major / 🟡 Minor / ⚪ Trivial

## 1. Логика регистрации (Frontend + Backend)

| # | Сев. | Баг | Шаги / ожидание / факт |
|---|---|---|---|
| 1 | 🔴 | **UI показывает успех, даже если регистрация не прошла** | Отправить форму, на которую бэкенд отвечает 400 (или бэкенд выключен). **Ожидание:** сообщение об ошибке, пользователь остаётся на форме. **Факт:** редирект на «Thank you for subscription!», в консоли uncaught `Request failed with status code 400`. Причина: `Auth.tsx:38-39` — `AuthService.sendUser(data)` без `await`/`catch`, `navigate("/success")` вызывается сразу. |
| 2 | 🔴 | **Правила пароля на фронте и бэке не совпадают** | Пароль `password1`. Фронт: валиден (кнопка активна). Бэк: `400 ERROR: invalid password` → вместе с багом №1 пользователь «зарегистрирован», а аккаунта нет. Обратно: `Passw0rd-`, `Passw0rd^` валидны для бэка, но фронт их отклоняет. Фронт (`shared/regex.ts`): буква+цифра, спецсимволы только `@$!%*#?&`. Бэк (`regex.config.ts`): заглавная+строчная+цифра+спецсимвол `#?!@$%^&*-`. |
| 3 | 🟠 | Текст ошибки пароля не соответствует проверке | Сообщение «at least one uppercase letter, one lowercase letter and one number», но фронт не требует ни заглавной, ни строчной (`password1`, `PASSWORD1` проходят); про спецсимвол не сказано, хотя бэк его требует. |
| 4 | 🟠 | **Валидация телефона отключается нажатием Backspace** | Ввести `1234`, нажать Backspace, оставить `1`. **Ожидание:** ошибка «at least 8». **Факт:** поле валидно, на сервер уходит `"phone_number":"1"`. Причина: `AuthFields.tsx:20-25` — `onKeyDown` делает `setMinLength(0)`; там же забытый `console.log('delete')`. |
| 5 | 🟠 | Смена пароля после подтверждения блокирует форму без объяснения | Заполнить форму валидно → изменить «mot de passe». **Факт:** кнопка «S'inscrire» неактивна, ни одной ошибки не показано; поле подтверждения не перевалидируется (нет `trigger("confirmPassword")`). |
| 6 | 🟠 | Нет проверки уникальности email | Дважды отправить одни и те же данные → 2 записи (`id 2` и `id 3` в БД). Нет unique-индекса и проверки. |
| 7 | 🟡 | Нет индикатора загрузки/обработки ошибок сети | При недоступном API — тот же ложный успех (№1). |

## 2. Валидация полей (Frontend)

| # | Сев. | Баг | Детали |
|---|---|---|---|
| 8 | 🟠 | Имена с диакритикой и не латиницей отклоняются | `Hélène`, `François`, `Иван` → «Please enter a valid first name». Для франкоязычного сайта критично. `nameRegex = /^[a-z ,.'-]+$/i`. |
| 9 | 🟠 | Мусор принимается как имя | `.....`, `--- '`, `   John   ` (пробелы не обрезаются) — валидны. |
| 10 | 🟠 | Минимум 4 символа для имени/фамилии | `Bob`, `Max`, `Li`, `Ng` — реальные имена отклоняются. |
| 11 | 🟡 | Max длина имени зависит от браузера | `AuthFields.tsx:37`: `!navigator.userAgent.includes("Chrome") ? 40 : 28`. В Chrome/Edge 28, в Firefox/Safari 40 (проверено с UA Firefox: 35 символов проходят), а сообщение всегда «less than 28». |
| 12 | 🟡 | Тексты «less than N characters» неверны | Ровно 28 (имя/пароль) и 16 (телефон) символов допускаются → должно быть «at most N». |
| 13 | 🟡 | Телефон: нельзя ввести `+` и международный формат | `+33612345678` → ошибка; пробелы/скобки/дефисы тоже. |
| 14 | 🟡 | Неверный текст ошибки формата телефона | При буквах/`+` выводится «Ce champ est requis» («Поле обязательно»), хотя поле заполнено. |
| 15 | 🟡 | Фамилия: текст ошибки про имя | `Smith1` → «Please enter a valid **first** name» под полем фамилии (`AuthFields.tsx:61`). |
| 16 | 🟡 | Чекбокс согласия: пустая ошибка | Отметить и снять → рендерится пустой `<span>`, без текста (у `required` нет `message`). |
| 17 | ⚪ | Email с пробелом в конце отклоняется | `x@y.com ` → «valid email» ошибка, значения не триммятся. |

## 3. Backend / API (`POST /users/create`)

| # | Сев. | Баг | Шаги / факт |
|---|---|---|---|
| 18 | 🔴 | **Перезапись чужого пользователя (mass assignment)** | `{"id":1, "first_name":"HACK", ...}` → 201, запись `id=1` в БД **перезаписана** (имя, email, пароль). DTO сохраняется в `repository.save()` как есть. |
| 19 | 🔴 | **Пароли хранятся в открытом виде** | `select password from users` → `Passw0rd!`. Нет хеширования (bcrypt/argon2). |
| 20 | 🔴 | **Пароль пишется в лог** | При `DEBUG=true` (по умолчанию в docker-compose) `console.log('Server received...', createUserDto)` выводит пароль открытым текстом. |
| 21 | 🟠 | Нет серверной проверки типов и длины | Принимаются: `is_agree:"no"`, `first_name:123`, `last_name:{"a":1}` (в БД `{"a":1}`), имя 5000 символов, телефон 60 цифр, имя из пробелов `" "`, `<script>alert(1)</script>`. Нет ValidationPipe/class-validator, DTO — просто класс. |
| 22 | 🟠 | Отсутствующее поле → 500 вместо 400 | Без `last_name` → `500 Internal server error` (NOT NULL violation). Проверка `validateData` перебирает только присланные ключи. |
| 23 | 🟡 | Неверные значения считаются «пустыми» | `phone_number: 0` → «field is empty» (проверка `!value`). |
| 24 | 🟡 | Email не нормализуется | `A@B.COM` и `a@b.com` — разные пользователи. |
| 25 | 🟡 | В ответе лишнее поле `is_agree`, не совпадает с `ShowUserDto` | Поле не сохраняется в БД (нет колонки), но возвращается; факт согласия не хранится. |
| 26 | 🟡 | `GET /` → 404 | `AppController`/`AppService` не подключены в `AppModule` — health-эндпоинт «Service is working!» недоступен. |
| 27 | 🟡 | CORS `*`, нет rate limit | `Access-Control-Allow-Origin: *`; можно массово регистрировать с любого сайта. |
